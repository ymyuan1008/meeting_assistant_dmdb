# 第三方令牌接口对接文档

本文档面向第三方系统，用于对接并获取访问业务接口所需的认证令牌（JWT）。请严格按照本文档的签名与时间戳规则构造请求头。

## 接口概述
- 接口路径：`/api/v1/third-party/token`
- 请求方法：`GET`
- 认证方式：`Header` 签名验证（参数名：`token`）
- 响应格式：`application/json`

## 请求头说明
- 参数名：`token`
- 必填：是
- 格式：`appId-{appId}#timestamp-{timestampMs}#sign-{sign}`

参数含义：
- `appId`：应用ID（需与服务端配置一致）
- `timestampMs`：当前时间戳，单位毫秒（Unix Time in milliseconds）
- `sign`：签名值，算法为 `md5(appId + appSecret + timestampMs)`（MD5 Hex，小写/大小写均可，服务端不区分大小写）

签名示例（Python）：
```python
import hashlib
import time

appId = "aihear"
appsecret = "<your_app_secret>"
timestamp = str(int(time.time() * 1000))

sign_str = appId + appsecret + timestamp
sign = hashlib.md5(sign_str.encode()).hexdigest()

header_token = f"appId-{appId}#timestamp-{timestamp}#sign-{sign}"
```

## 验证规则
1. 时间窗口验证：请求到达时，服务端会验证 `timestampMs` 与当前时间的差值，默认仅接受 `THIRD_PARTY_TIMESTAMP_VALID_WINDOW=300` 秒（5分钟）内的请求；超出则返回过期错误。
2. 签名验证：服务端使用相同的算法重新计算签名并与请求中 `sign` 比对，不一致则返回签名错误。
3. 应用ID验证：`appId` 必须为服务端注册且配置的有效应用ID，否则返回无效应用ID错误。

## 成功响应示例
HTTP 200：
```json
{
  "code": 200,
  "message": "成功",
  "data": {
    "access_token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
    "token_type": "Bearer",
    "expires_in": 3600,
    "scope": "api"
  }
}
```

字段说明：
- `access_token`：JWT 令牌，用于后续业务接口认证
- `token_type`：令牌类型，固定为 `Bearer`
- `expires_in`：令牌有效期，单位秒（由服务端 `THIRD_PARTY_ACCESS_TOKEN_EXPIRE_MINUTES` 转换而来）
- `scope`：权限范围，固定为 `api`

## 错误响应示例
- 签名验证失败（HTTP 401）：
```json
{ "code": 401, "message": "无效的签名", "data": null }
```
- 请求超时（HTTP 401）：
```json
{ "code": 401, "message": "请求已过期", "data": null }
```
- 无效应用ID（HTTP 403）：
```json
{ "code": 403, "message": "无效的应用ID", "data": null }
```
- 服务端未正确配置 JWT 密钥（HTTP 500）：
```json
{ "code": 500, "message": "服务未正确配置JWT密钥", "data": null }
```

## 请求示例

### 使用 curl（跨平台）
```bash
APP_ID="aihear"
APP_SECRET="<your_app_secret>"
TIMESTAMP=$(date +%s%3N)  # 毫秒时间戳
SIGN=$(echo -n "${APP_ID}${APP_SECRET}${TIMESTAMP}" | md5sum | awk '{print $1}')

curl -X GET "http://your-api-domain/api/v1/third-party/token" \
  -H "token: appId-${APP_ID}#timestamp-${TIMESTAMP}#sign-${SIGN}" -v
```

### Windows PowerShell（推荐在 Windows 环境）
```powershell
$APP_ID = "aihear"
$APP_SECRET = "<your_app_secret>"
$TIMESTAMP = [Int64]([DateTimeOffset]::UtcNow.ToUnixTimeMilliseconds())

$raw = "$APP_ID$APP_SECRET$TIMESTAMP"
$md5 = [System.Security.Cryptography.MD5]::Create()
$bytes = [System.Text.Encoding]::UTF8.GetBytes($raw)
$hash = ($md5.ComputeHash($bytes) | ForEach-Object { $_.ToString("x2") }) -join ""

$token = "appId-$APP_ID#timestamp-$TIMESTAMP#sign-$hash"
$url = "http://your-api-domain/api/v1/third-party/token"

# 发起请求
Invoke-WebRequest -Method GET -Uri $url -Headers @{ token = $token }
```

## 服务端配置（参考）
服务端从环境变量中读取以下配置：
- `APP_ID`：应用ID
- `APP_SECRET`：应用密钥
- `JWT_SECRET` 或 `JWT_SECRET_KEY`：JWT 签名密钥
- `JWT_ALGORITHM`：JWT 算法，默认 `HS256`
- `THIRD_PARTY_ACCESS_TOKEN_EXPIRE_MINUTES`：令牌过期时间（分钟），默认 `1440`
- `THIRD_PARTY_TIMESTAMP_VALID_WINDOW`：时间窗口（秒），默认 `300`

## 后续使用
获取到 `access_token` 后，第三方系统在访问业务接口时，请在请求头携带：
```
Authorization: Bearer <access_token>
```

## 常见问题（FAQ）
- 提示“请求已过期”：请检查本机时间是否准确，以及 `timestampMs` 是否为毫秒单位；可在允许窗口内重试。
- 提示“无效的签名”：请确保签名字符串为 `appId + appSecret + timestampMs`，且采用 UTF-8 字符集进行 MD5 计算。
- 提示“无效的应用ID”：请确认 `appId` 与服务端配置一致（区分大小写）。
- 提示“服务未正确配置JWT密钥”：联系服务端管理员检查 JWT 密钥是否已设置。
