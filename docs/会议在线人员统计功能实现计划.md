# 会议在线人员统计功能实现计划

## 1. 背景与目标
- 目标：在会议进行中，实时统计“在线人员”，并提供在线人数与在线列表的查询接口，同时向客户端广播在线状态的变化。
- 在线人员定义：满足以下全部条件的用户被计为在线：
  1) 已通过 JWT 登录认证（access token 有效且未撤销）；
  2) 已参与该会议（存在 `Participant` 记录，或签到状态为已签到）；
  3) 与会议的“在线状态”WebSocket通道保持活跃连接，并按约定发送心跳。

## 2. 现状梳理与选型
- WebSocket连接管理：
  - `db/conn_manager.py`：按 `meeting_id -> List[WebSocket]` 维护连接，提供 `connect/disconnect/broadcast`；目前无法按用户维度统计。
  - `websocket/manager.py`：按 `client_id` 与 `room_id` 维护连接与元数据，具备更细粒度能力，但当前路由使用的是 `db.conn_manager.ConnectionManager`。
- 路由使用：`router/attendance_manage.py`、`router/meeting_manage.py` 都导入了 `db.conn_manager.ConnectionManager`。
- 认证：`services/auth_service.py` 与 `services/auth_dependencies.py` 已提供 JWT 生成与验证逻辑。
- 会议与人员模型：`services/service_models.py` 中的 `Meeting`、`Participant`、`PersonSign`，以及对应服务层 `meeting_service.py`、`sign_in_service.py`。

选型结论：保持现有路由对 `db.conn_manager.ConnectionManager` 的依赖，增量扩展其能力以支持“在线人员统计”，避免大范围替换；保留后续统一为 `websocket/manager.py` 的可能性。

## 3. 在线判定规则
- 鉴权：连接时通过 JWT `access token` 验证（在 WebSocket 握手或首帧携带 token），拒绝未认证连接。
- 参会校验：
  - 优先：查询 `Participant` 是否存在且状态合法（如 `attendance_status` != 已离开）。
  - 可选：结合 `PersonSign`，仅统计已签到人员（场景需要时开启）。
- 心跳：客户端每 `30s` 发送一次心跳，服务端若 `60s` 未收到，判定离线并清理。
- 多设备：同一用户可多设备连接，统计在线时按“用户维度去重”。

## 4. 架构与数据结构设计
- 扩展 `db.conn_manager.ConnectionManager`：
  - 新增内存结构（示意）：
    ```python
    meeting_users: Dict[str, Dict[str, PresenceInfo]]
    
    class PresenceInfo(BaseModel):
        sockets: set[WebSocket]        # 同一用户的多连接
        last_seen: datetime             # 最近心跳或消息时间
        metadata: Dict[str, Any]        # name/role/device/client_id 等
    ```
  - 保留原有 `meeting_id -> List[WebSocket]` 结构，用于房间广播；新结构用于用户维度统计。
- 关键方法（接口草案）：
  - `connect_presence(meeting_id, user_id, socket, metadata) -> None`
  - `heartbeat(meeting_id, user_id) -> None`
  - `disconnect_presence(meeting_id, user_id, socket) -> None`
  - `get_online_users(meeting_id) -> List[Dict[str, Any]]`
  - `get_online_count(meeting_id) -> int`
  - `broadcast_presence_event(meeting_id, event: Dict[str, Any]) -> None`（事件型广播）

## 5. WebSocket 路由设计
- 新增路由文件：`router/presence_manage.py`
- 端点：`/ws/meetings/{meeting_id}/presence`
- 握手参数：
  - Header：`Authorization: Bearer <access_token>`（推荐）或 Query：`?token=<access_token>`（备选）
  - 可选 Query/首帧：`client_id`、`device`、`role`
- 服务端流程：
  1) 验证 token（`auth_service.verify_token(..., 'access')`），解析 `sub=user_id`。
  2) 读取用户与参会信息（`user_service.get_user_by_id`，`meeting_service`/`Participant` 校验）。
  3) 调用 `connect_presence` 入房间并记录元数据；广播 `presence.join`。
  4) 处理心跳帧 `{"type":"presence.heartbeat"}`，更新 `last_seen`。
  5) 连接关闭或超时：调用 `disconnect_presence`；广播 `presence.leave`。
- 事件与消息格式（建议）：
  - `presence.join`：`{"type":"presence.join","meeting_id":"...","user":{"id":"...","name":"...","role":"..."},"online_count":N}`
  - `presence.leave`：同上；
  - `presence.snapshot`：`{"type":"presence.snapshot","meeting_id":"...","online_count":N,"users":[...]}`（定期或按需推送）；
  - `presence.heartbeat`：客户端 -> 服务端，服务端不广播，仅更新状态。

## 6. HTTP API 设计
- `GET /api/meetings/{meeting_id}/online-count`
  - 返回：`{"meeting_id":"...","online_count":N}`
- `GET /api/meetings/{meeting_id}/online-users`
  - 返回：`{"meeting_id":"...","users":[{"id":"...","name":"...","role":"...","last_active":"..."}],"online_count":N}`
- 权限：仅会议管理员或参会人员可查询本会议在线状态。
- 性能：列表分页（默认返回前 200），支持按 `role`/`name` 过滤。

## 7. 与签到与参会逻辑的结合
- 策略开关：
  - `presence.require_sign_in = false`（默认：仅验证 Participant）。
  - 当 `true`：需要 `PersonSign` 为已签到状态才计入在线人数。
- 参会与离会：
  - 可在 `sign_in_service` 中调用 Presence 接口做联动（如签退触发 `presence.leave`）。

## 8. Redis 与多进程/多实例支持（可选增强）
- 目标：当服务多实例部署时，实现跨实例在线状态一致性。
- 设计：
  - Key 设计：
    - `presence:{meeting_id}` -> `SET` of `user_id`
    - `presence:{meeting_id}:{user_id}` -> `HASH`/`STRING`（存放 `last_seen`、`device` 等），设置 TTL（如 90s）
  - 心跳处理：每次心跳刷新 `presence:{meeting_id}:{user_id}` 的 TTL；若 Key 过期由定时任务清理 `SET`。
  - 事件广播：`pub/sub` 渠道 `presence.events.{meeting_id}`，跨实例分发 `join/leave/snapshot`。
  - HTTP 查询优先从 Redis 读取，内存作为本地缓存。

## 9. 数据模型与审计（可选）
- 需求：保留在线历史轨迹（加入/离开），便于审计与问题排查。
- 新增表（示例 DDL，按使用数据库调整类型）：
  ```sql
  CREATE TABLE presence_history (
    id BIGINT PRIMARY KEY,
    meeting_id BIGINT NOT NULL,
    user_id BIGINT NOT NULL,
    action VARCHAR(16) NOT NULL,     -- join/leave
    occurred_at TIMESTAMP NOT NULL,
    device VARCHAR(64),
    client_ip VARCHAR(64),
    INDEX idx_meeting_time (meeting_id, occurred_at)
  );
  ```
- 触发：`connect_presence` 记录 `join`，`disconnect_presence` 记录 `leave`。

## 10. 安全与治理
- 鉴权与授权：
  - JWT 校验、黑名单（已有）；
  - 仅允许已参与会议的用户连接 presence 通道；
  - 管理员可查询全量在线数据；普通参会者仅可见摘要（可选）。
- 限流与防滥用：
  - 心跳频率限制（最小间隔 10s）；
  - 连接并发上限（每用户最多 3 连接，可配置）。
- 隐私：仅暴露必要字段（不返回邮箱/手机号等敏感信息）。

## 11. 监控与可观测性
- 指标：
  - `presence_online_count{meeting_id}` 当前在线人数；
  - `presence_join_total/leave_total` 事件计数；
  - 心跳延迟分布（P50/P95）。
- 日志：`presence.join/leave/snapshot` 事件按会议维度打点。
- 报警：心跳超时过多、连接异常激增。

## 12. 验收标准
- 能够稳定维护在线人数与列表，加入/离开/超时均正确更新；
- HTTP 接口返回与 WebSocket 广播一致；
- 在单实例与多实例（开启 Redis）场景下均工作稳定；
- 安全策略生效，拒绝未授权访问；
- 性能：1k 并发连接下心跳与广播无明显延迟（<200ms）。

## 13. 开发拆解任务（实施顺序）
1) 扩展 `db/conn_manager.py`：新增用户维度的 `meeting_users`、`PresenceInfo` 及相关方法。
2) 新增 `router/presence_manage.py`：实现 `/ws/meetings/{meeting_id}/presence` 路由，完成鉴权、参会校验、心跳与断线处理、事件广播。
3) 新增 HTTP 接口：`/api/meetings/{meeting_id}/online-count` 与 `/api/meetings/{meeting_id}/online-users`（在 `router/meeting_manage.py` 或新建 `presence_manage.py` 中）。
4) 与签到/参会逻辑的配置化结合：在服务层增加策略开关，按需启用 `PersonSign` 约束。
5) 单元与集成测试：模拟多设备心跳、断线重连、权限校验；验证计数与列表。
6) （可选）Redis 集成：实现多实例下的状态共享与事件分发；配置项与部署说明。
7) 监控与告警：接入指标、日志规范；压测并调整心跳与超时时间。

## 14. 接口契约示例
- 客户端加入（首帧示例）：
  ```json
  {"type":"presence.join","client_id":"<uuid>","device":"web","role":"participant"}
  ```
- 心跳：
  ```json
  {"type":"presence.heartbeat","ts": 1730000000}
  ```
- 服务端快照广播：
  ```json
  {"type":"presence.snapshot","meeting_id":"123","online_count":3,
   "users":[{"id":"1","name":"Alice","role":"HOST","last_active":"2025-01-01T10:00:00Z"}]}
  ```

## 15. 兼容性与迁移建议
- 保持现有 `db.conn_manager` 的列表广播不变；新增用户维度能力并行存在。
- 若后续统一到 `websocket/manager.py`：以 `client_id/room_id` 为核心，分阶段迁移路由与广播调用，确保对外契约不变。

## 16. 配置项（建议）
- `PRESENCE_HEARTBEAT_INTERVAL_SEC`（默认 30）
- `PRESENCE_TIMEOUT_SEC`（默认 60）
- `PRESENCE_REQUIRE_SIGN_IN`（默认 false）
- `PRESENCE_MAX_CONNECTIONS_PER_USER`（默认 3）
- `PRESENCE_ENABLE_REDIS`（默认 false）及 Redis 连接配置

---
实施备注：本计划在不破坏现有路由与广播能力的基础上，增量加入用户维度在线统计；先内存实现，后视部署架构与并发量启用 Redis 扩展以支持多实例部署与更高并发。
